後台與個資紅線

能存資料是這次的新能力，
也是風險等級跳一階的地方。這一頁請讀完再動手。

01

為什麼這件事變重要了

以前 AI 生出來的是靜態網頁，學生點完就沒了，資料不留存，所以最壞的情況也只是東西不好用。現在不一樣——你在持續蒐集資料，而且是關於特教學生的資料。

特教場景有一個普教沒有的問題：間接識別。資料表裡即使一個名字都沒有，只要這套系統是發給資源班或巡迴輔導使用的，「這筆資料存在」本身就洩漏了障礙身分。這比你想的更難迴避，所以要從設計時就處理。

02

紅線

七條。做不到就不要接後台，靜態版本一樣可以用。

▲不可跨越
  • 只存隨機碼或代號。姓名、學號、身分證號一律不進系統，對照表留在學校端紙本。
  • 不存障礙類別、鑑定文號、班級型態。不要出現「資源班」「特教班」字樣，連欄位名稱都不要。
  • 狀態欄位用中性代碼。存 audio 不要存「需要報讀」，存 selected 不要存「無法書寫」。
  • 跨校部署每校一個獨立專案。不要全縣共用一個資料庫，否則跨校比對就能識別。
  • 資料保留期限現在就訂。寫進系統說明，時間到就刪。
  • 蒐集前走學校既有的個資告知同意程序。不要因為是內部工具就跳過。
  • 先問過縣市教育處的資安規範。資料庫是境外服務，跨境傳輸這件事你不能自己決定。

今天現場一律用假資料。不要因為「只是測試」就把真實資料丟進去測試環境——測試環境的資料一樣是資料。

03

權限實測

02:25 互檢那一段一定要做這個。三十秒的事。

資料表如果沒有設好列層級權限，任何人拿到網址就能撈到整張表。這是這類專案最常見也最嚴重的事故，而 AI 生成的程式碼未必會幫你設。

  1. 開一個無痕視窗
    或換一個瀏覽器，總之要一個完全沒登入的環境。
  2. 貼上你的系統網址
    看列表頁載不載得出資料。載得出來就是壞的。
  3. 問 AI 要 API 網址，直接打開
    更徹底的測法。問它「這個專案的資料表 API 端點是什麼」，把網址貼到無痕視窗。如果回傳一整張表的 JSON，就是全開的。
  4. 壞的就叫它修，然後再測一次
    指令：「請為所有資料表開啟列層級安全性，未登入使用者不得讀取或寫入任何資料，並告訴我怎麼驗證。」改完一定要重測，不要相信它說改好了。

這一項排在無障礙檢核前面。無障礙沒做好，有人用得辛苦；權限沒設好，是不可逆的事故。順序不要顛倒。

04

欄位怎麼設

通則是：能回答你的問題的最少欄位。

先寫下你想回答的問題，再倒推欄位。不要先設欄位再想能幹嘛——那樣一定會存太多。

教材與評量類系統的參考欄位。行政類請依你自己的問題重設。
欄位存什麼回答什麼問題
session_id隨機碼，每次開啟生成不綁身分也看得出使用行為
unit_code單元代碼跨班跨校可比的唯一鍵
path_chosentext／audio／diagram哪個入口真的有人用
path_switch_count切換次數換來換去表示三條都不好用
response_modetyped／selected／spoken多元作答有沒有被用到
task_id correct time_on_task題目、對錯、耗時入口與表現有沒有關聯

沒有姓名、沒有學號、沒有障礙類別、沒有班級型態。這組欄位就能回答「有聲入口的使用率多少」「用了之後正確率有沒有差」「哪個單元大家一直換路徑」。換路徑特別頻繁的單元，就是你的設計有障礙。

05

三個要回去問的事

沒有技術解，只有行政解。

  • 誰付費、掛在誰的帳號下。免費方案有容量與專案數上限，一校一個專案很快會撞到。
  • 維運歸屬。你調動之後這個系統誰接？帳號綁在個人身上，人一走就斷。
  • 跨境傳輸的資安規範。問縣市教育處，不要自己決定。
