團務行政：排程、紀錄與經費

團務資料散在各團員手上，彙整時才發現對不起來。
具備資料留存能力一項，為本次功能更新之實質意義所在。

須建置資料庫團務層級第一天下午
第一天下午 輔導團層級之題目。校長與團務承辦人員宜自此三類擇一 延伸：資料儀表板 →
01

問題界定

團務行政的負擔具有共同結構：同一份資料散在各團員手上，且無單一權威版本。到校服務紀錄在各自的筆記本，時數統計在承辦人的試算表，對外報送的表又是第三份。彙整時才發現三者對不起來。

試算表無法承擔此類需求之原因，在於其不具真正之資料庫結構：多人同時編輯易生衝突，亦不支援以行動裝置即時登錄。具備後端資料庫後，此類業務方具備系統化之條件。

常見題目

團員與輔導區分配
誰負責哪幾所學校、本學期已服務幾次、哪幾所還沒排到
到校服務排程與紀錄

02

實作（一）：輸入介面

第一天下午。應先建置輸入端，統計報表後續處理。

常見之失敗模式為優先建置統計儀表板。無人登錄即無資料，儀表板將維持空白。應先將登錄流程簡化至可實際執行之程度。

  1. 記錄現行作業流程
    如實記錄，包含所有冗餘步驟。「開啟甲檔複製，開啟乙檔貼上，再手動修改日期」一類敘述即為系統規格之來源。
  2. 刪減至最少必要欄位
    逐欄檢視：缺少該欄位將產生何種影響。無實質影響者予以刪除。欄位數與登錄意願呈反比。
  3. 配合行動裝置之使用情境
    實際使用情境多為站立於教室後方登錄，而非於辦公桌前操作。應加大按鈕、增加選項、減少文字輸入。
  4. 完整執行一次並計時
    不宜以測試資料略作點選即認定完成。應自起始至結束完整執行，並記錄所需時間。逾兩分鐘即屬過長。
康軒 KUSE 指令
請建置一個〔個別化教育計畫進度追蹤／教具借用／巡迴輔導紀錄〕系統，
使用者為〔特殊教育教師／輔導員〕，主要於〔行動裝置〕上使用。

現行作業流程為：〔如實描述，含所有冗餘步驟〕

請建置下列功能：
1. 輸入介面，欄位數盡量精簡，可選填者不採文字輸入
2. 資料寫入後端資料庫，再次開啟時資料仍存在
3. 歷史紀錄列表，可依〔日期／學校／服務類型／團員〕篩選
4. 個人時數統計，供團員自行查閱及核銷使用

個人資料規則（須嚴格遵守）：
- 服務對象僅記錄人數與類型，不得設置學生姓名、代號或班級欄位
- 團員以職稱與服務學校表示，不得設置聯絡方式欄位
- 不得設置障礙類別、鑑定文號、班級型態等欄位
- 資料表須設定列層級安全性，未登入者不得讀取任何資料

無障礙規格：字級至少 20px、點擊區至少 44×44px、
對比度 4.5:1 以上、全程可僅以鍵盤操作、不以顏色單獨傳達狀態。
03

實作（二）：資料庫與權限驗證

第一天下午後半。本主題最關鍵之環節。

行政資料之敏感度高於教材資料，其性質即為關於特定學生之紀錄。存取權限設定不當者，等同於將特殊教育學生名冊置於公開網址。

建置方式、蒐集限制與權限驗證程序詳見資料庫建置與個人資料保護。選擇本主題者請完整閱讀該頁。

▲行政系統之特有風險
  • 不記錄至個人。服務紀錄僅記人數與類型；一旦出現學生代號，整份資料集之敏感度即行跳升。
  • 資料累積性：教材資料多於一學期後停止蒐集，團務資料則逐年累積。保留期限應於建置時即行訂定。
  • 多人使用：系統建置後同仁將沿用。何人得檢視何等資料，應於設計階段即行界定。
  • 維運歸屬：帳號綁定於個人，人事異動後系統之接續維護無人負責。本項無技術解決方案，須循行政程序處理。
04

三向度檢核

本主題之使用者為同仁，其中同樣存在視覺辨識或操作條件受限者。
多元表徵
於走廊、單手持行動裝置、強光環境下能否辨識
  • 字級與對比度是否足夠
  • 狀態是否單獨以顏色表示
  • 欄位名稱是否採用僅建置者理解之簡稱
多元行動與表達
能否於兩分鐘內完成登錄
  • 文字輸入量能否改以選項替代
  • 點擊區是否達 44×44px 之下限
  • 登錄中途中斷後返回，已填內容是否留存
多元參與
團員改採本系統之誘因為何
  • 是否減少一項其現行必須執行之步驟
  • 既有資料能否匯入，抑或須重新登錄
  • 登錄後能否自動產出個人時數，供差旅與鐘點核銷使用

末項為本主題成敗之關鍵。團務系統推行失敗多非技術因素，而在於使用習慣之轉換成本。若系統僅係將工作負擔自承辦人員轉移至團員，其存續期通常不逾一學期。
